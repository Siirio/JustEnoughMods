# Explicit non-test quality configuration

`gradle/module-settings.gradle` reads `tools/module-inventory.json` as the single
module list. It rejects malformed/duplicate entries, missing declared Java builds,
retired/upstream modules accidentally entering the first-party Java graph, and
module build directories missing from the classification inventory.
Production artifact selection continues to use that inventory; development target
coverage never authorizes distribution.

When separately authorized to execute quality tooling, use the root wrapper:

```powershell
.\gradlew.bat -PjemQuality=true qualityCheck --no-configuration-cache
```

Without `-PjemQuality=true`, ordinary builds neither resolve the quality plugins
nor register their tasks. The aggregate invokes only `spotlessCheck`,
`checkstyleMain`, `pmdMain`, `spotbugsMain`, and root `cpdCheck`. It never invokes
`check` or `test`. Existing test disables remain. SpotBugs requires main class
compilation through its normal producer dependencies. Nothing installs, stages,
publishes, or launches Minecraft.

Versions are pinned in `gradle/java-quality.gradle`: Spotless 6.25.0,
google-java-format 1.22.0 (AOSP layout, existing import order), Checkstyle 10.17.0,
PMD/CPD 7.7.0, SpotBugs plugin 6.0.26 and engine 4.8.6. Checkstyle and PMD rules
live in their adjacent configuration directories. There are no package-wide
suppressions, failure swallowing, arbitrary class-size thresholds, or debt baseline
that silently accepts findings. CPD uses 100 exact tokens without identifier or
literal normalization; all nonzero exit codes fail and its XML report is retained.

Source tools consume each included module's active `main.allJava`, excluding
normalized paths under its build directory and `src/generated`. This includes
active Professions profiles and omits inactive Roles `src/development`. GuiSandbox
mirrored sources are generated build outputs, so source tools do not double-count
their production authorities. SpotBugs consumes the complete compiled main output
and the plugin's main auxiliary classpath; this deliberately also
covers generated bytecode. Missing dependency errors are not suppressed.

This configuration has not been executed or calibrated against existing findings.
A configured strict task is not a passing gate. No CI workflow or branch protection
was installed. Test-based architecture, codec, lifecycle, server-linkage and
regression suites remain excluded by the user's no-tests instruction. Existing
architecture metrics and artifact inspection tools retain their separate purposes;
this configuration does not fabricate test coverage from their reports.

Metrics source scope also comes from `tools/module-inventory.json`: default main
roots, declared additional resource roots, and the selected source profile.
`--profile professionProfile=sandbox` matches a Gradle sandbox build; omit it for
the declared production default. Profile overrides must match the build whose
scope is being compared. Generated build mirrors and inactive source profiles are
excluded. For `--revision`, the manifest is read from that revision. A revision
without one fails with a clear message unless `--historical-mode` is explicitly
selected; that mode reports its old all-module main/generated scope and must not
be presented as a like-for-like active-inventory comparison. Metrics execution
still requires separate authorization; none was performed for this change.
