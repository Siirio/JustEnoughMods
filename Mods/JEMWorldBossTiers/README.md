# JEM World Boss Tiers

One logical-server owner for world progression, boss profiles/scaling, hosted encounters, native arena/revival identity and non-item progression rewards. Item entitlements belong to mandatory `jem_rewards [1.0.0,)`. The production implementation supports integrated worlds and dedicated hosts; client presentation uses the same synchronized state. Required metadata: Forge `[47.4.10,)`, Minecraft `[1.20.1,1.21)`; builds target 1.20.1. Iron's Spells is optional behind its audited adapter. See the [complete domain inventory](../../Docs/universal/README.md).

## Progression and persistence

`WorldTierData` retains SchemaVersion 2, historical unique defeats, arena aliases/live-UUID claims, respawn queues and Raid participation. A fresh world captures actual registered qualifying bosses and a reachable threshold profile. Full content retains 0/3/10/18/32; reduced content scales the original thresholds proportionally, keeps them strictly increasing and omits unreachable tiers. The world persists that profile. Removing content later does not reduce its thresholds, remove historical proof or auto-award a tier. Existing saves without the new profile retain the original configured roster/thresholds. Very small fresh rosters can expose fewer than five reachable tiers.

`StructureEncounterApi` owns native structure associations at `data/jem_server/jem/events/structures/campaigns.json`, loaded-only discovery and the existing arena UUID derivation. It inspects current loaded chunks and already-loaded reference origins, then delegates registration/native-anchor proof to `RaidArenaApi`. Server uses this API rather than a second association map. Revivals and Raid cleanup retain one canonical living-boss claim and one verified native anchor; unknown/unloaded entities are not absence proof.

## Admission and combat

On dedicated hosts, registered hosted bosses/support remain dormant until canonical Start. Without optional Server, ordinary solo admission remains available. JEM Raid requires dedicated hosting and Server; preparation changes provenance/lobby state only. At Start, exact accepted participants and combined Raid/party strength are frozen once. Integrated/LAN ordinary bosses use native combat without hosted confirmation, preserving World Tier and campaign prerequisites.

Actual-death elimination, native arena identity and ordinary boss recovery retain their canonical owners. The explicit 2026-10-24 restoration reuses the JEMServer shared structure-volume barrier for dedicated Boss Fight/Campaign/Raid without changing this module's canonical arena or combat authority. Item loot copies enter JEMRewards using boss UUID plus attempt UUID; legacy non-item advancement/recovery state remains here. Shared ordinary Minecraft XP is x2 through ExperienceRewardApi and the narrow orb intake seam, before Mending with a scoped remainder transfer. Race/profession XP and saved XP recovery are separate. Matching TierNetwork protocol remains 6; standalone Raid selection is denied.

Boss/reward data formerly in Pack Core now lives in this module. Public IDs and save names remain unchanged. Encounter behavior is documented in [Boss Fight](../../Docs/events/BOSS_FIGHT.md) and [Boss Raid](../../Docs/events/BOSS_RAID.md); source/build ownership is in [DEVELOPMENT](../../Docs/DEVELOPMENT.md). Runtime/gameplay acceptance is not established by these source contracts.
