# JEM World Boss Tiers

One logical-server owner for world progression, boss profiles/scaling, hosted encounters, native arena/revival identity and non-item progression rewards. Item entitlements belong to mandatory `jem_rewards [1.0.0,)`. The production implementation supports integrated worlds and dedicated hosts; client presentation uses the same synchronized state. Required metadata: Forge `[47.4.10,)`, Minecraft `[1.20.1,1.21)`; builds target 1.20.1. Iron's Spells is optional behind its audited adapter. See the [complete domain inventory](../../Docs/universal/README.md).

## Progression and persistence

`WorldTierData` retains SchemaVersion 2, historical unique defeats, arena aliases/live-UUID claims, respawn queues and Raid participation. A fresh world captures actual registered qualifying bosses and a reachable threshold profile. Full content retains 0/3/10/18/32; reduced content scales the original thresholds proportionally, keeps them strictly increasing and omits unreachable tiers. The world persists that profile. Removing content later does not reduce its thresholds, remove historical proof or auto-award a tier. Existing saves without the new profile retain the original configured roster/thresholds. Very small fresh rosters can expose fewer than five reachable tiers.

`StructureEncounterApi` owns native structure associations at `data/jem_server/jem/events/structures/campaigns.json`, loaded-only discovery and the existing arena UUID derivation. It inspects current loaded chunks and already-loaded reference origins, then delegates registration/native-anchor proof to `RaidArenaApi`. Server uses this API rather than a second association map. Revivals and Raid cleanup retain one canonical living-boss claim and one verified native anchor; unknown/unloaded entities are not absence proof.

## Exclusive arena ownership and legacy migration

World Tier enrollment, scaling and first-defeat progress belong to each registered entity profile. They do not by themselves grant exclusive arena ownership. `BossProfile.ownsExclusiveArena()` selects hosted profiles, an explicit arena strategy or JEM-owned respawning. Ordinary enrolled mobs with no arena strategy and native revival retain their own encounter tier, provenance, participants and defeat eligibility without competing for one arena UUID.

The original log contains 119 repeated warnings for 41 distinct conflicting mobs and four saved keepers. Read-only native entity-region evidence retains all 45 UUIDs. The installed Collapsed Kingdom templates intentionally contain several Guards, Knights and Fractured mobs. The causal chain is: chunk reload re-observed each legitimate mob, the common spawn/load path registered it into a shared radius arena, that arena admitted only one living UUID, World Tier enrollment had been treated as exclusive ownership despite the profiles disabling hosted arenas, and death handling reused that same exclusive-UUID gate. Repeated warnings and skipped direct defeat handling therefore shared one ownership error. A REVIVAL provenance label alone cannot identify an illegitimate duplicate and is never a deletion criterion.

After profile load or reload, existing SchemaVersion 2 WorldTierData archives inappropriate active/live/conflicting/retired claims and creation or revival intent under `NonExclusiveArenaHistory`. Raw historical arena geometry and every defeat, threshold and roster remain saved. Operational arena lookups exclude those historical ordinary-mob records so they cannot shadow real offering arenas or re-enter Raid reservations. Known loaded UUIDs shed only obsolete arena and creation holds. Native Paladin support membership and its canonical structural arena remain authoritative. Unloaded entities reconcile on their ordinary load path without forced chunk loading or entity deletion.

The user requested development-profile delivery only. Existing worlds are migrated by the updated save owner when loaded, rather than being patched offline. Artifact and delivery evidence is in `Docs/events/nonexclusive-ownership-delivery-20261025.json`. Runtime migration and player acceptance remain unrun.
