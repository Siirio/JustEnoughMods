# FTB and Xaero integration

FTB Quests `2001.4.22` remains an observational guide. Achievement Guide owns the one marked universal book projection, using exact native FTB Library/Teams APIs and stable quest/task IDs. Actual registered content and host domain APIs determine availability before native parsing. Missing/off goals become hidden inert historical records, preserving their original maxima and native team completion/claim data. Five current race choices observe RaceApi; strict TwelveEyes completion observes CampaignApi, never twelve ordinary Ender Eyes. Events are inactive in integrated worlds and dedicated hosts without explicit event opt-in. Professions is development-only and does not become a production quest requirement. The bridge grants no XP, Coins, race, boss or town state; interface/planning checkmarks remain only for the action they actually represent. Source contract and unexercised reload/UI limits: [Achievement Guide](../../Mods/JEMAchievementGuide/README.md).

Building projects use the existing JEM/Xaero map protocol v8. The server persists authenticated owner, dimension, name, stable color, source rectangles, collaborators and revision. Positive-area overlap merges visually; edge/corner contact does not. Removing a source rectangle deterministically recomputes components on the client. Limits are 20 projects per owner, 64 source rectangles per project, 1,000,000 union blocks² and two mutations per second.

Project regions are metadata and rendering only. `RegionPermissions` exposes no block, chest, PvP, door, teleport or interaction permission decision. Xaero Regions `1.0.8` is intentionally not installed because its exact metadata requires Forge `47.4.20`, incompatible with JEM's pinned `47.4.10`.
