# Phase 2 manual acceptance

No automated tests or runtime scenario is created by this document. Use the dedicated `test jem` profile if a later prompt explicitly authorizes a manual launch. Do not use the stable profile.

1. Do this: outside every founded town, throw an apple by a villager and place a flowerpot. → Expected that: native behavior is unchanged; JEM creates no resident mood or amenity record.
2. Do this: authenticate, found a town at a bell, then sneak-use the bell on an adult villager with a valid home/worksite. → Expected that: the Hall lists one resident with persistent mood/home/work evidence, while the migrated town keeps its original UUID, owner, anchor, storage and aggregate happiness.
3. Do this: lower a registered resident below 60 satiety and throw a stack of 64 apples within three blocks. → Expected that: exactly one apple is removed, eating feedback plays, mood receives +1 or the repeated-food damped value, and an immediate repeat is blocked for 12,000 game ticks; a satiated resident ignores it.
4. Do this: offer rotten flesh or a poisonous potato, then offer verified `bakery:vegetable_sandwich`. → Expected that: one unsafe item applies -6 with no positive breeding nutrition; the installed sandwich applies +5, subject to cooldown and rolling caps.
5. Do this: place distinct vetted amenity categories around a linked home/worksite, then place 100 identical lanterns and break the original lamp. → Expected that: the Hall names recognized evidence; duplicates stop at their category/state cap, cannot maximize happiness, and the broken light is reconciled after the 60-second debounce without loading remote chunks.
6. Do this: prepare two eligible adult residents with real beds and normal food; separately try one sandwich with no spare bed. → Expected that: only native paced breeding can occur with real capacity and same-town registration; one meal never directly spawns a child, and an unsanctioned child remains native until valid adult registration.
7. Do this: register exact native Recruit, Bowman and Captain types and fund 180 Copper, then allow 168,000 monotonic game ticks; repeat with only 170. → Expected that: the first roster costs exactly 1 Gold + 8 Silver once with no soldier tax or native second charge; the short treasury loses nothing and shows a 1 Silver shortfall. Reload/retry stays idempotent, missed periods penalize native morale once each, and recovery uses native readiness.
8. Do this: unload every relevant town chunk for four game days with all players away, then return. → Expected that: no forced ticket kept the town active; one catch-up records at most the verified four-day interval. Workers output remains zero with `No supported remote evidence` until Workers exposes a safe production contract; no pending item becomes real or sellable by reopening the Hall.
9. Do this: leave while another player keeps a registered work/storage area loaded. → Expected that: native activity remains authoritative and the same interval is not remotely simulated.
10. Do this: move, fill or remove a linked chest before a future supported materialization. → Expected that: the obligation is quarantined rather than dropped or overwritten. Current Workers output/materialization is safely disabled, so the journal must show no invented delivery; restart retains the recorded interval state.
11. Do this: rewind or advance `/time`, stop the server for a real day, and later return after 20 genuinely elapsed game days. → Expected that: wall time adds nothing, rewinds cannot repay an interval, and catch-up models at most six days once while logging the other fourteen as skipped idle; payroll keeps its separate monotonic seven-day schedule.
12. Do this: inspect an unloaded mining town with no verified ore/input contract. → Expected that: it produces no diamonds, boss tokens, Eyes, rare drops or tradeable phantom stock.
13. Do this: authenticate as a non-owner and attempt treasury, roster or project mutation; repeat while identity is locked. → Expected that: the stranger receives only permitted read-only information and every account mutation fails closed without trusting packet account IDs.
14. Do this: genuinely tame ten new eligible mounts, remount one UUID repeatedly, reconnect, and tame distinct audited types. → Expected that: lifetime count reaches ten once, repeat/death/reconnect does not increment it, type progress is personal `x/12`, and each persisted milestone/reward flag can be awarded only once; admin/spawn-egg/creative acquisitions do not qualify.
15. Do this: observe an unloaded town and a loaded return with profiling tools during an explicitly authorized manual run. → Expected that: unloaded JEM entity/pathfinder work is zero; catch-up admits at most four town calculations, amenity scans at most eight resumable sites and 64 blocks per cursor/tick. Physical project materialization is disabled without authored permission-safe blueprints, so its block-update count is zero and cannot exceed the reserved 32-global/8-town contract.
