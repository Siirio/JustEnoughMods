# Backpacked: direct Workbench augment

Owner: JEMCompat feature/backpack and narrow mixin/backpack adapters around installed Backpacked3.0.9 / Framework0.8.0. No patched third-party JAR or replacement screen.

## Player flow

Open the equipped backpack, choose an unlocked native augment bay and click Workbench. Successful native selection immediately enables that augment and refreshes the native backpack screen with a3×3 ingredient grid and one result slot between backpack/player inventories. No workshop, lapis fee, crafting-table payment or purchase entitlement. Native bay unlocks, disabled types, duplicate selection, other augment settings and backpack limits stay upstream-owned.

Changing/removing/toggling an augment refreshes only when the actual enabled/unlocked crafting layout differs from installed menu slots. Ingredients remain on the same backpack under JemWorkbenchIngredients: removing/disabling Workbench preserves them, re-enabling restores them.

The retired jemcompat:augment_bay block/item identities and placed-block geometry remain only for existing saves. Recipe, creative/JEI entry, interaction, menu/screen, payment code and purchase messages are removed. Existing JemWorkbenchPurchased metadata is ignored without rewriting saves.

## Inventory and authority

Only the equipped owner's native BackpackContainerMenu gains crafting; docks, shelves and pickpocket views keep their native lifecycles. Existing backpack/player slot indices remain;9ingredients and vanilla ResultSlot append after them. Player inventory moves80px down and the crafting insert occupies that space. Shift-click preserves backpack/player direction and sends crafting inputs/results to player inventory. Native ResultSlot owns consumption, remainders, hooks and rewards; partial shifted results drop like vanilla CraftingMenu. Result pick-all is blocked.

Server RecipeManager, limited-crafting policy and enabled features determine results; the result is never saved as an extra claimable item. Native BackpackInventory.isAllowedItem governs ingredient slots, container setters, remainders and persistence. Invalid loaded/in-place-mutated ingredients are removed before return to player inventory/drop, without deletion or nested-container bypass.

Universal source update, 2026-10-22: integrated worlds now use the same native Workbench/Furnace/Auto Feed augment registrations and logical-server processing as dedicated hosts. The old integrated augment-list hiding adapter is removed. Clients render synchronized menu state and never own crafting outcomes.

## Furnace and Auto Feed —2026-10-20 implementation candidate

User task13 requests two additional native augments while retaining Workbench. Native `jemcompat:furnace` and `jemcompat:auto_feed` use Backpacked3.0.9's existing codec registry, unlocked bays, enable state, duplicate/disabled policy and selection packets. No replacement backpack or detached station. Successful native selection enables the selected augmentation; layout refresh compares actual installed Workbench and Furnace slots independently. Native3×3 Workbench ingredients and its cream icon remain unchanged.

Furnace adds actual input/fuel/output slots after the existing slots. The compact112×80 native panel sits to the right of Workbench when both are enabled, with a4px gap in one228×80 row. A single active panel stays centered112×80. Shared geometry moves player slots/rendering together; viewport scrolling retains native popup priority. The Furnace uses the authored native-size cream/shadow PNG described below; Auto Feed retains the native Apple item asset; the existing native Backpacked panels and vanilla furnace flame/progress texture are reused. No new painted or generated artwork ships. These source choices are Codex implementation decisions based on the user's native-interface requirement, not visual acceptance.

`BackpackInventoryProcessMixin` extends the inspected native `BackpackInventory.tick()` lifecycle. Native `stillValid(owner)` checks the living owner and exact equipped ItemStack reference. The logical server owns all progress; when Identity is installed, its canonical IdentityPolicy also gates account mutation. Without that optional module, native server player-session authority remains. State is one `BackpackFurnace` attached to that native inventory, serialized into its exact backpack's `JemFurnace` NBT after every mutation: three stacks, remaining fuel, cooking progress, recipe identity and accumulated recipe XP. Unequipping, death, logout and disabled augmentation pause it; no wall-clock catch-up occurs. Transferring the backpack transfers its contents and progress, not a player-global cache.

Smelting uses the server RecipeManager's real SMELTING recipe, cooking duration, assembled enabled result and Forge fuel duration. The output must fit before fuel is consumed; blocked output never gets discarded. Fuel containers replace the final fuel item; nonempty remainders with stacked fuel are refused before consumption rather than dropped or lost. Recipes with an input crafting remainder are explicitly refused pending an exact consumption adapter. Ordinary shift-click direction remains backpack↔player; appended crafting/furnace slots shift to the player's actual capacity. Native FurnaceResultSlot preserves crafting hooks; a real output take awards accumulated native recipe XP/unlocks once. Recipe XP persists through removal/reload. Progress/fuel sync uses split integer halves so long modded fuel durations survive native16-bit menu packets.

Auto Feed runs from the same actual equipped native storage. It checks native hunger acceptance, first eligible food, unlocked slot/admission and a finite40-native-step cooldown shared across equipped backpacks. It calls FoodData directly, consumes exactly one portion and saves native contents immediately. It never starts hand use, invokes finishUsingItem, plays eating audio or emits eating particles. Ordinary-food support follows native FoodProperties, including nutrition/saturation, and requires inherited vanilla Item.finishUsingItem (resolved by its exact runtime method name); modded subclasses with unchanged consumption are supported. Effectful, always-edible, NBT-bearing or custom-consumption foods are refused unchanged until an exact opt-in adapter exists. No effect-food adapter or opt-in is supplied in this candidate. Containers with native crafting remainders reserve a valid return slot before consumption. This conservative refusal is an explicit safety boundary, not a claim that all installed meals are handled.

Exact inspected interfaces: BackpackedInventoryAccess.backpacked$streamNonNullBackpackInventories (on Player), BackpackInventory.getBackpackStack/getState/tick/saveItemsToStack/stillValid, BackpackHelper.findAugment/getUnlockableAugmentBays, native BackpackContainerMenu constructors and native AugmentType codecs. Framework0.8.0 FrameworkTexture and AugmentIcons remain presentation owners. The former integrated exclusion is superseded by the universal source update. Matching Compat/native Backpacked/Framework contracts apply to client/server; Identity is metadata-optional and its adapter remains authoritative when installed. No gameplay launch, automated test or player acceptance was performed; capacity, death/transfer/reload, native picker and scaled viewport gestures remain manual acceptance questions.
