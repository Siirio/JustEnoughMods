# Universal JustEnoughMods

Current source contract: 2026-10-22. One Forge 1.20.1 / Forge 47.4.10 / Java 17 production pack supports integrated singleplayer and matching dedicated JEM hosts. Windows, Linux and macOS use the same gameplay JARs. This describes implemented source boundaries and packaging, not completed gameplay, optional-mod or OS acceptance.

[Install the universal archive](INSTALL.md). Engineering/distribution ownership remains in [DEVELOPMENT](../DEVELOPMENT.md); financial policies remain in [economy documentation](../economy/overhaul-implementation.md), and encounter rules remain in [Boss Fight](../events/BOSS_FIGHT.md) and [Boss Raid](../events/BOSS_RAID.md).

## What standalone means

A standalone domain installs on a fresh compatible Forge instance with its explicitly required foundations and those foundations' own dependencies. It does not require the complete JEM modpack, a launcher-specific profile, a network backend or an unrelated JEM gameplay domain. It does not mean every JEM JAR has zero dependencies. Economy, Races and Settlements each retain their own JAR and require Identity; Races also requires the preserved Lodestone particle renderer. Create is genuinely required by the drill addon. Server is a combined host module with the hard dependencies listed below.

After the files and required libraries are installed, integrated gameplay is local and offline. Multiplayer requires its host and matching gameplay modules. Client presentation cannot provide absent server authority or override world settings. Adaptive Culling and Luxium integration are client-only; arbitrary non-JEM-server compatibility is not established for the remaining shared modules.

## Preserved domain boundaries

- Economy is enabled by default through the world's SERVER config `[economy] enabled=true`. Off suspends Coin spending/earning/conversion, payment and currency UI without deleting Coins, balances or financial records. Settlements uses its existing emerald provider when Economy is absent/off; it does not exchange one currency into the other. Authored prices and native offer/restock behavior remain owned by their existing sources.
- Races has one state owner and the existing five IDs: `ancestors`, `void_walkers`, `born_in_bloom`, `infected_by_sculk`, `nether_hearteds`. Human/Dwarf/Elf survive only as legacy aliases, not a second roster. `jem_roles` saves, developed powers, translations, assets and legacy network/resource namespaces remain preserved.
- WorldTier adapts a fresh world's qualifying roster to actual registrations, then persists that roster and its thresholds. The full pack retains 0/3/10/18/32 unique-defeat thresholds. Later removal of content cannot lower the stored thresholds or manufacture victory. Twelve Eyes never substitutes another boss, Eye or prerequisite to match an incomplete roster.
- A new incomplete Twelve Eyes world keeps its campaign inactive and its vanilla End path available. An existing active campaign with missing content retains state and fails closed at MAIN Start/portal with explicit diagnostics until that content returns. This is availability handling, not a campaign victory.
- The explicit 2026-10-24 request restores the old dedicated Boss Fight/Campaign/Raid visible structure-volume walls, collision and teleport restrictions through the shared arena owner. An attempted dormant boss hit opens admission without damage; canonical Start validates prerequisites, exact participation and scaling. Actual death ends that attempt. Blood Moon and Resource Rush retain their own event boundaries.
- `JEMServer` registers shared resources/network, but `EventRuntime.enabled(server)` requires a dedicated host and `jem-events-server.toml` `enabled=true`, default false. Ordinary solo/party boss Raid is a non-seasonal encounter and does not require that event switch. Installing the event assets alone does not enable a scheduler in singleplayer.
- The one FTB book observes owner APIs and actual registered content. Missing/off activities become hidden inert records while stable quest/task IDs and native team progress remain. Race choice and strict campaign completion are never inferred from proxy item inventory.

## Retired owners and development exclusions

CurrencyCore is merged into Economy. Pack Core's complete developed source/resources are distributed to Achievement Guide, Compat, WorldTier, TwelveEyes and Server. Required Menu Support controls are private native helpers in their consuming modules. Races absorbs the developed VisualSandbox scope. Do not install CurrencyCore, Pack Core, Menu Support, an old separate Roles/Races artifact or VisualSandbox as an extra production companion. Preserved Java/content namespaces do not imply another runtime mod.

Professions, Villager Talking and Claims remain development-only and are excluded from the original/shareable pack. They may remain in an explicitly permitted sandbox/development profile; this document does not promote them. Professions retains its Pufferfish-owned progression contract rather than a new XP ledger. Talking remains text-only. Villager Workers and Saints Dragons remain excluded under their separate current project rules.

## Archive, bootstrap and evidence boundary

`python tools/jem.py package-universal` writes `Client/JustEnoughMods-universal.zip` from the full included managed source and the matching bootstrap, with `jem-pack/manifest.json` and a SHA-256 inventory. It excludes launcher version JSON/JAR/options, saves, runtime/authentication files and personal map state. It is installed into a fresh compatible Forge instance following [INSTALL](INSTALL.md). The existing `package-full` remains the bootstrap-only installer workflow for native connection-driven acquisition.

Bootstrap revision `jem.9` keeps the native AutoModpack downloader/planner/CAS/hash/trust/transaction owners. Its source change fixes long-path acquisition/projection through the native file-tree transfer boundary and replaces repeated warnings/countdowns with a file list, one risk consent and Download. It does not approve executable bytes, reset ownership, bypass integrity or turn publication into proof of installation. Bootstrap is included with the shareable archive but remains separately updated from the served managed pack.

Shaders are optional and disabled by default in the shared Oculus configuration. JEM Luxium adds one native Embeddium page that selects an installed `Luxium ` shader through the exact Oculus 1.8.0 API. It remembers the previous Oculus shader and enabled state before switching, then restores both when turned off. If Luxium was selected outside this adapter and no prior state exists, turning it off returns to normal Oculus rendering with shaders disabled. The included shader archives are choices for compatible graphics drivers, not a claim that every shader supports every OS. In the installed `Bloop-1.8.0-Alpha-3.zip`, `shaders/world1/shadow.fsh` requests GLSL `430`; installed Oculus `1.8.0` preserves that version during transformation. Apple's native macOS OpenGL support stops at 4.1, so that End shadow program exceeds the supported version. [Apple's platform explanation](https://developer.apple.com/videos/play/wwdc2020/10631/) establishes the API limit; no shader rendering or fallback was exercised here. Select a shader only after checking its own GPU/OS requirements.

The installed Epic Fight `20.14.17` has a narrower optional native cosmetic service: its Linux helper is ELF x86-64, while both bundled macOS helper paths contain a thin ARM64 Mach-O library. Linux ARM64 and Intel macOS JVMs therefore cannot load those respective helpers. Native load failure is caught, and the observed `supported()` guard uses the default cape instead. This limits that online cosmetic feature; it does not establish a gameplay or startup failure. Bootstrap's bundled Windows x86-64 DLL is separately guarded by OS/architecture and is not required on Linux or macOS.

A source edit, archive or successful production compilation does not establish gameplay, native Mixin loading, optional-mod matrix, visual acceptance, first-install recovery or Windows/Linux/macOS runtime parity. Those outcomes require their own authorized evidence. No game launch or acceptance is claimed by this documentation update; stable profiles, MineRENT and the immutable release baseline keep their existing release boundary.
