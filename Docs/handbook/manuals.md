# Native manual routes in the JEM Handbook

This is an implementation coverage ledger, not a gameplay registry. Sources are the exact installed archives in `Client/ManagedPack/mods` on 2026-10-22, their native data resources and `javap -p -c` bytecode. Nothing in this document claims an exercised game session. Native GUI navigation and player discoveries remain owned by each mod.

Source review resumed on 2026-10-23 after the independent FTB delivery. There are **eight connected general-manual families**: seven native registered manual items plus Iron's registered Patchouli book. Aquamirae adds a ninth family of acquired NBT-bearing lore documents, with one card per distinct carried variant. These are route/inventory counts, not a runtime registration dump or proof of GUI acceptance. The eight physical item IDs (the seven general manual items and Aquamirae) each have exactly one matching record in their existing `Catalog/registries/items/<mod_id>.json`, with source SHA-256 matching the inspected archives. Iron's book identity comes from its native `book.json`, and the adapter additionally checks the native `BookRegistry.INSTANCE.books` map before accessing it.

## Safety and navigation contract

`NativeManuals.available()` builds cards on opening/rebuilding the manual list, not every hover frame. It checks mod presence and registered destination items. Optional native client class names are resolved only inside their guarded action; native Patchouli destination registration is checked before stack lookup. Failure logs the exact adapter error and gives a localized visible message instead of opening an invented screen.

`CommonManuals.register()` registers the `jem_advancements:native_manuals` channel. Its C2S payload is one unsigned byte selecting exactly CNC, Luminous Beasts or Unearthed Journey. Server validation requires a live player carrying the real Patchouli JEM Handbook (`patchouli:book=jem_advancements:just_enough_guide`), rejects an already open container, bounds request cadence and takes coordinates from the server player. It cannot request arbitrary classes, pages, IDs, NBT, grants or positions. Native `execute` signatures and their initial menu constructors were inspected; no item-use/consume/advancement/research operation is called.

The common channel class imports no `net.minecraft.client` class and has no client type in its fields, request codec or handler. Its optional native procedure classes are literal names resolved only after the owning mod guard, on the server work queue. `NativeManuals` is reached only from the guarded client bootstrap/Handbook screens. No FTB bridge, quest asset or progression owner is referenced or changed by these adapters.

The parent Handbook navigation retains the actual originating screen, arms return before the action, accepts only that manual's confirmed native screen family and closes server containers before returning. MCreator opens arrive asynchronously through the native screen packet. Only these Unearthed screen families are guide pages: `JourneyGuidePage1Screen`, `GettingStartedPage1..3Screen`, `EnvironsPage1..4Screen`, `ToolsNItemsPage1..5Screen`, `UniqueAnimalsPage1..4Screen`. Satchels and nests are not guide screens. Normal close/unrelated screens clear the return session; the return action does not globally intercept game screens.

## Reproduction and archive identity

Read archives without launching Minecraft. For each owning class, use `javap -classpath <exact-jar> -p -c <fully-qualified-class>`; compare item use -> helper/procedure -> screen/menu, including player state access. ZIP JSON/lang names are discovery candidates, not proof of registration. `Catalog/generator/query_web_mechanics.py find <mod_id>` was consulted alongside installed evidence for the connected mods and exclusions; its historical snapshot/version warnings were retained as uncertainty, not promoted to current behavior.

Actual installed API receipt:

- Patchouli 1.20.1-85, `vazkii.patchouli.api.PatchouliAPI$IPatchouliAPI`: `void openBookGUI(ResourceLocation)`, `void openBookEntry(ResourceLocation, ResourceLocation, int)`, `ItemStack getBookStack(ResourceLocation)`. `vazkii.patchouli.common.book.BookRegistry` exposes `public static final INSTANCE` and `public final Map<ResourceLocation, Book> books`. The native-manual route uses `openBookGUI` only; it does not select a locked entry.
- Tide: `public static void com.li64.tide.client.TideClientHelper.openJournalScreen()` constructs `FishingJournal(Player)` with the actual local player. `TideEventHandler.onPlayerJoinWorld(ServerPlayer)` synchronizes native player data; the adapter does not call the item-use path's consume-item trigger or used-item statistic.
- Alex's Caves: `com.github.alexmodguy.alexscaves.client.ClientProxy.openBookGUI(ItemStack)` constructs `new CaveBookScreen()`, which delegates to `books/root.json` and reads actual `CaveBookProgress` from the player. The argument is not converted into synthetic research NBT.
- Alex's Mobs: `com.github.alexthe666.alexsmobs.client.gui.GUIAnimalDictionary(ItemStack)` forwards the item display context and native title to Citadel `GuiBasicBook`; its native root is `alexsmobs:book/animal_dictionary/root.json`.
- Blast From The Past: `public static void team.recrafted.blastfromthepast.util.ClientUtils.openGlacialGuidebookScreen()` is the exact helper invoked by `GlacialGuidebookItem.use` on the client.
- CNC, Luminous Beasts and Unearthed Journey: each procedure listed in the coverage table exposes exactly `public static void execute(LevelAccessor, double, double, double, Entity)`. Their item use methods invoke those procedures. Each opens the native server menu via `NetworkHooks.openScreen`; the inspected initial menus allocate an `ItemStackHandler(0)` and do not bind or expose a synthetic book inventory.
- Aquamirae: `public static void dev.obscuria.aquamirae.client.AquamiraeClientHelper.openLogbookScreen(ItemStack)` constructs native `LogBookViewScreen(ItemStack)`. `LogBookItem.getTopic` and `getContent` read serialized components under `topic` and `content`; acquired variants are copied without altering either field.

The source-only review also checks the parent return integration: it arms the return session before calling the unchanged `Manual.open()` API, adds the button through `ScreenEvent.Init.Post`, retains the originating screen object and closes a native server container before returning. Candidate Iron's screens are recognized by the candidate `GuiBook.book.id`, rather than consulting the previous/current screen while a `ScreenEvent.Opening` transition is in flight. The first acquired Aquamirae card keeps stable ID `aquamirae`, so its static Handbook chapter remains a valid action after acquisition.
