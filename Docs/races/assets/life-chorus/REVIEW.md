# Golden Chorus — reference review

Status: ART_CANDIDATE. Source/assets and build delivery are separate from Minecraft
runtime evidence and user approval.

Exact Pair: Taste-Engine/Pairs/Minecraft/VFX/Forge-1.20.1-jem-race-abilities.
Primary current reference: references/user-chorus-direction.png, supplied by the
user explicitly for Chorus. Observed major qualities: a rising coherent gold swirl,
ornate pointed ground rune, luminous diamond/cross motes, restrained orbit connector,
recognizable small shields and surviving fragments. Four outward shields/5s remain
explicit user requirements despite different numbers printed in that image.

I_like183623 was also reopened: stepped major bodies, unequal thickness, bright
lips and intentional interior gaps. Online analogue search included Minecraft
Dungeons Radiance and the official Healing Wind image:
https://www.minecraft.net/en-us/store/minecraft-dungeons-cloudy-climb-adventure-pass
These are contextual proposals, not user taste or sources of copied artwork.

History: orange bars were USER_REJECTED for lacking healing/nature direction and
individual recipients. The first botanical replacement also failed agent review
as two weak repeated lines; broad leaf masses improved it, but the user's subsequent
gold storyboard now supersedes that study. Its moving/contact evidence survives as
green-study.gif/green-study-contact.png. Do not mistake it for the current output.

Current revision uses original generated production cels, not recolored bars or
crops from the reference. Rune reveal/held highlight/dissolution, swirl curl/climb/
release and individual diamond motes have distinct poses. Rune's slight generated
pivot offsets are aligned losslessly. Runtime and moving evidence use the same
native384x256 art and actual outward-facing R7 mesh. Alpha inspection found that
broad-looking amber RGB in the sheet background actually has zero alpha; export
preserves it without adding a visible rectangular glow.

Second agent rejection: enlarging the whole rune to16 blocks made its central
petals huge opaque spokes. Revised actual production: keep the hero rune local,
author a separate open-center engraved gold_front sheet and use that for both
shared waves. This changes rendered assets/placement, not only documentation.

Current critique: the generated rune has one dominant circular band plus pointed
petals, less nested engraving than the supplied board. The swirl is a camera-facing
sprite conveying near/far overlap, not a volumetric helix mesh; side/orbit camera
readability still needs real game evidence. Repeated highlight poses are subtle
and the dissolution is short. These limits are explicit; compilation and a neutral
stage do not prove world depth, first-person readability or uneven terrain fit.

The shared player-origin wave owns both entry and V knockback; no golem-centered
shockwave or recurring aura. Entry is one trigger after successful addFreshEntity.
V aligns its shared wave with server healing. Neither cue invents extra damage.

Evidence: gold-contact.png, gold-assets.json, editable gold_*.aseprite and original
production-sheets; life-chorus.gif is actual asset/native-mesh playback, NOT Minecraft.
Installation receipt and CHANGELOG record build results. No automated tests,
scenarios or gameplay launch. New art remains pending user acceptance.
