# One-shot: реализовать FTB Quests для JustEnoughMods

Ты работаешь в репозитории **Siirio/JustEnoughMods**. Реализуй полноценную, удобную и визуально законченную книгу **FTB Quests для Minecraft Forge 1.20.1 / Java 17**, используя приложенный HTML как подробный проект содержания. Выполни изменения в файлах сборки, ресурсах и необходимых интеграциях. Результат должен работать в игре. Одного плана, HTML-макета или нескольких демонстрационных глав недостаточно.

Главная цель: игрок через понятные действия знакомится со всем игровым содержанием пака, получает щедрую и полезную награду из модов и понимает, что попробовать дальше. Сохрани свободу прохождения и простоту реализации условий. Внешний вид — аккуратная книга приключений с настоящими игровыми фонами и пиксельными иконками, по принципам приложенных референсов Homestead.

## 2. Сохрани весь охват и понятный порядок

Исходная спецификация содержит **32 вкладки и 596 карточек**: 533 с одной простой проверкой, 36 с двумя, 27 справочных/резервных; среди игровых заданий — 153 коллекции. Таблица покрытия содержит 287 mod IDs, включая служебные моды, которым отдельные задания не нужны.

- Перенеси все 32 тематические вкладки и содержание всех 596 карточек. Сохрани соответствие исходным ID и номерам. Не заменяй конкретные механики несколькими общими заданиями «изучи мод».
- Создай таблицу соответствия `HTML ID → глава → FTB ID/информационный элемент → условия → награда → статус`. Проектные ID из HTML не выдавай за готовые числовые FTB IDs. Уже существующие FTB IDs и сохранённый прогресс сохраняй, где смысл задания остаётся тем же; изменения проводи с явным сопоставлением.
- Справочные и резервные карточки остаются доступной справкой: без награды, ручной галочки, обязательных зависимостей и влияния на процент завершения. Если версия FTB не поддерживает подходящий информационный узел, используй описание главы или другой штатный информационный элемент, сохранив запись в таблице соответствия.
- `after` и «Порядок знакомства» в HTML — **рекомендации**, а не готовые обязательные dependencies. Передай их расположением, короткими указателями и переходами. Обычные действия и коллекции должны засчитываться без предварительного получения награды за соседний квест.
- «Открывает контент» обычно означает объяснение следующей механики. Не добавляй новые блокировки рецептов, торговли, предметов или измерений. Реальные ограничения кампании остаются у исходного мода/JEM.
- Если мод удалён, предмет отключён или механика изменилась, отрази конкретное расхождение и адаптируй соответствующую карточку. Не подставляй выдуманный registry ID и не оставляй невыполнимое обязательное задание. Отсутствующий контент исключается из доступного завершения с объяснением, а не исчезает из отчёта о покрытии.

## 3. Условия: одно понятное действие, максимум два

Сложность оценивается по семействам действий и необходимому состоянию, а не по количеству предметов. **Поставить 23 разных блока — одна коллекция событий «поставить».** Она не превращается в 23 связанных этапа. Несколько простых Item tasks внутри фиксированной коллекции допустимы.

Разрешённая основа: наличие предмета, размещение/разрушение блока, завершение еды или питья, удар с уроном, получение урона, смерть противника, ПКМ предметом/по блоку/по существу, посадка на транспорт, смена измерения, обычный крафт/выемка из печи, существующий нативный флаг или маленький callback из места успешной операции.

| Пример | Что именно проверять |
| --- | --- |
| Поставить кровать и факел | Одно семейство placement; отметить две целевые группы. Не оценивать спальню. |
| Собрать 8 разных блюд | Наличие явно заданных разных типов; восемь экземпляров одного блюда не подходят. |
| Съесть определённую еду | Завершение употребления нужного предмета, а не наличие в инвентаре. |
| ПКМ по животному с указанным предметом | Одно взаимодействие, тип цели и предмет в руке. Не заявлять успешное приручение, если проверяется только попытка. |
| Страж защитил игрока | В событии положительного урона атакующий — нужный страж; жертва — `Mob`, текущая AI-цель которой — этот `ServerPlayer`. Зачёт этому игроку. Без истории боя, территории и ожидания таймера. |
| Победа MAIN | Уже существующий подтверждённый флаг кампании с правильной областью действия, без повторного сценария «найти → активировать → сразиться». |

У двух условий по умолчанию независимый AND. Не добавляй связанный сценарий длиннее двух событий. Для обычной карточки достаточно флага, счётчика либо набора ключей коллекции.

**В зачёт не входят:** оценка территории, комнат, площади, формы постройки, красоты сада, работоспособности всей фабрики, доставки по маршруту, истории происхождения товара, длительного поведения моба или последовательности действий из подсказки. Не заменяй такие проверки тикающим обходом мира.

Для коллекций зафиксируй список целей, теги и необходимые NBT-различия; различай «по одному из каждой группы», «любые N разных» и «N экземпляров». Не потребляй предметы без прямого требования. Повторная установка одного типа не должна заполнять разные позиции коллекции. Поставленный, а затем убранный блок остаётся изученным, если задание требует факт размещения.

## 4. Реализация прогресса и наград

Используй штатные FTB tasks/rewards там, где они точно подходят. Для остального сделай небольшой общий мост событий, а не отдельный Java-класс на каждый квест и не универсальный сценарный движок.

- Сервер подтверждает прогресс. Индексируй активные условия по типу события и цели; не обходи все 596 карточек при каждом ударе и не добавляй собственный постоянный опрос всех инвентарей.
- Проверяй отмену события, нужную руку, игрока и цель. Нормализуй дубли взаимодействий, `EntityMultiPlaceEvent` и повторную доставку callback. Счётчики сохраняются после выхода, смерти и перезапуска согласно принятой модели прогресса.
- Название задания должно честно соответствовать наблюдаемому действию. Наличие предмета не доказывает личный крафт. `RightClickItem` не доказывает успешное использование механики. Для задачи о нанесённом уроне проверяется положительный фактический рассчитанный урон через подходящее событие установленной версии.
- Нативные флаги читай из действующего источника. Пометка `callback` в HTML означает предлагаемую новую интеграцию, а не существующий метод. Например, улов Tide и успешная торговля должны сообщаться из проверенного места результата операции; не восстанавливай их по произвольному появлению предмета в инвентаре.
- Не путай FTB-команду хранения прогресса, временную боевую party, личную задачу и мировой флаг кампании. Заранее определи scope каждой категории. Нативный мировой флаг не является доказательством личного участия в бою.
- Сохрани **щедрые предметные награды из обновлённого HTML и `REWARDS.json`**, включая количество и выбор. Редкие полезные предметы разрешены за достаточно трудные задания. Не уменьшай всё до ванильной еды, нескольких слитков или XP. Награды выдаются однократно согласно явно выбранному scope, без дублирования после переподключения или изменения команды.
- **Не выдавай оружие боссов и готовое снаряжение Nightfall.** Eyes, обязательные ключи и доступ к этапам кампании остаются у нативной системы. Редкость сама по себе не является запретом: небоссовые аксессуары, инструменты, подходящая броня и редкие материалы допустимы за заслуженные достижения. Не вводи повторяемый источник монет.
- Сохрани все 12 оригинальных MAIN и их реальные SUB-требования. Отсутствие мода не даёт права заменить обязательного босса другим; отображай ограничение именно кампании. Не смешивай необязательных боссов с обязательной кампанией.

Учитывай более поздние решения пользователя, если HTML содержит старые упоминания: **`/smp`, боевая party и Raid недоступны в singleplayer; party на сервере нужна для масштабирования боссов и телепортации событий; отдельной системы профилей игроков нет.** Обычный прогресс FTB при этом должен работать соло. Не возвращай Profiles ради старых счётчиков HTML — используй действующий итог события либо один простой callback. Серверные задания не блокируют завершение доступного соло-контента.

Подключай награды к принятому в рабочей ветке способу выдачи. Если уже реализованы слоты получения слева от интерфейса, используй их: только извлечение, скрытие после опустошения, оформление через переопределяемые ресурсы. Не создавай параллельную систему Rewards/Profiles и не перестраивай всю экономику/SMP ради книги. Отсутствующую внешнюю интеграцию обозначь конкретно; остальные части выполни полностью.

### 4.1. Обязательная модель наград

В ревизии 3 у **всех 569 игровых карточек есть модовая предметная награда**; 27 справок/резервов остаются без наград. Использованы 774 разных модовых предметов из 55 пространств имён; 61 карточек дают выбор, 72 относятся к крупным или редким призам. Числа фиксируют текущую спецификацию, а не квоту, которую нужно искусственно набрать.

Игрок должен получать то, что помогает сразу продолжить интересную ветку: полезный инструмент, аксессуар, снасти, оборудование, большую партию строительных деталей или материалов, достаточное количество еды и расходников. Тематическая связь важнее принадлежности награды ровно тому же моду. После морского босса подходящая морская утилита из другого установленного мода — нормальный приз.

| Действительное усилие | Ориентир для награды |
| --- | --- |
| Первое действие, простой ПКМ, знакомство | Обычно 8–24 порции модовой еды, 16–64 расходника или небольшой полезный комплект. Не выдавай конечную редкую вещь за одно нажатие. |
| Освоение механики, несколько доступных предметов | Обычно 32–128 материалов, тематический инструмент или устройства для следующего этапа. |
| Дорогая коллекция, редкий улов, трудный противник | Редкий аксессуар/утилита, часть подходящего комплекта или осмысленный выбор плюс существенные припасы. |
| Длинный нативный рубеж, большой набор дорогих компонентов | Ценный предмет и крупные материалы; для стройки — 128–512 блоков/деталей. |
| Справка, резерв, неподтверждённый контент | Без награды и без влияния на завершение. |

Диапазоны — ориентиры, а точные количества находятся в карточках. Один предмет подходит для инструмента или редкого аксессуара; одна единица дешёвой еды — обычно нет. Оценивай сложность **реального условия**: «поставить восемь типов компонентов» не доказывает постройку железной дороги, а «войти в Незер» не доказывает межпространственный маршрут. Не добавляй скрытые проверки, чтобы оправдать дорогую награду.

В `REWARDS.json`:

- `items` — **всё гарантированно выдаваемое**. `count` означает итоговое количество, не число стаков. Например, 512 путей — 512 предметов, разбитых по реальному максимальному размеру стака; не создавай недопустимый ItemStack с количеством 512.
- `choice` — **ровно один вариант на выбор игрока**, дополнительно к `items`. У варианта может быть количество больше одного: например, два одинаковых орба — один вариант приза. Не выдавай все варианты сразу и не заменяй выбор случайным лутбоксом.
- `xp` — обычные **очки опыта**, не уровни. XP дополняет материальную награду. Не заменяй предметы равным по усмотрению разработчика количеством опыта.
- `tier` — дизайнерская категория ценности всей награды. Это не утверждение о нативной rarity каждого ItemStack. Если Atlas не подтверждает rarity, не придумывай её и не перекрашивай предмет.
- `reason` — конкретная польза награды; перенеси её смысл в короткий совет игроку. `notes` и сведения об источниках предназначены разработчику и не должны загромождать игровое окно.
- Выбор оформляй штатным механизмом установленной версии FTB, если он поддерживает нужную семантику. Проверь, что гарантированная часть остаётся отдельной, выбран ровно один вариант, отмена интерфейса не теряет право на приз. Не вводи новую валюту, магазин или отдельную платформу наград ради этой книги.

| `mg14`: победить Dead King | 4 легендарных чернил, 128 эссенции, 8 больших эликсиров дубовой кожи; **один на выбор**: Greater Conjurer’s Talisman, Ring of Recovery или Invulnerite Pickaxe. Точные локализованные названия и ID возьми из приложенной спецификации. |
| `eyes_15`: существующий флаг завершения всех 12 MAIN | Продвинутый беспроводной терминал Tom’s Storage, 8 легендарных чернил, 48 Arcane Ingots, 48 Deep Alloy Ingots, 16 больших эликсиров уклонения, 32 Chicken Wrapped in Bacon; дополнительно **один на выбор**: Tarantula Hawk Elytra, Invulnerite Pickaxe или Greater Conjurer’s Talisman. |

**Проверка по Atlas обязательна.** Сверяй точный registry ID, item model/регистрацию, нативное получение, применённые изменения JEM и текущие запреты. В статическом каталоге встречаются ключи локализации, подмодели, compat-кандидаты, предметы без survival-получения и отключённые записи. Сам факт строки в JSON не доказывает допустимость выдачи. При отсутствии статического вывода рецепта проверь исходный рецепт или регистрацию: некоторые модовые типы рецептов не полностью разобраны генератором Atlas. Не объявляй предмет несуществующим только из-за пустого `outputs` в таком графе.

Сверь [Item Obliterator](https://github.com/Siirio/JustEnoughMods/blob/9c10424f3d0f3dc10db54098ef173f8556932aa1/Client/ManagedPack/config/item_obliterator.json5) и [Atlas: оружие боссов](https://github.com/Siirio/JustEnoughMods/blob/9c10424f3d0f3dc10db54098ef173f8556932aa1/Catalog/power-sources/boss-reward-weapons-stage35.json). Запрещены также готовые Nightfall-предметы, creative/debug-вещи и яйца призыва. Не выдавай фальшивые пустые фотографии, свитки без заклинания, коробки с выдуманным содержимым и другие предметы, для которых требуется особый ItemStack. Для предмета с обязательными данными используй проверенный нативный способ создания либо подбери равноценный рабочий предмет из модов. Не придумывай NBT и не откатывайся автоматически к хлебу/XP.

Полученная награда может честно закрыть обычное задание на наличие того же предмета: история происхождения не требуется. Однако проверь **каскады наград**: дешёвое стартовое действие не должно автоматически завершить целую цепь и выдать дорогой финальный приз без соответствующего усилия. Исправляй конкретный состав награды, сохраняя простые условия и свободный порядок. Не награждай ключом, Eye или готовым оружием, которое заменяет смысл обязательной нативной победы. Материалы и ценные небоссовые предметы за настоящую победу допустимы.

Мировой флаг победы и личное участие в ней — разные основания. Если карточка в HTML проверяет мировой флаг, не заявляй в её тексте личную победу. Явно выбери существующую политику личного/командного права на одноразовое получение. Не придумывай длинную историю участия, тикающий наблюдатель боя или новую систему Profiles.

## 5. Удобные line-ups: требования к каждой главе

Расположение квестов должно помогать читать содержание. **Не превращай всю книгу в длинную цепь или случайную автосетку.**

1. У главы есть понятный вход, короткая вводная и узнаваемая иконка. Основной учебный маршрут читается слева направо либо сверху вниз; направление внутри одной группы не меняется без причины.
2. Начальные действия, развитие, коллекции и необязательные ответвления образуют отдельные компактные группы с короткими подписями. Параллельные темы идут параллельными рядами; коллекция выглядит как аккуратная полка предметов, а не обязательная цепь.
3. Используй единый шаг сетки, равные интервалы и выравнивание. Между обычными узлами оставляй заметный зазор; ориентир для расстояния между центрами — 1,6–2 диаметра узла, с поправкой на подписи. Между смысловыми группами больше воздуха.
4. Линии не проходят через другие узлы, заголовки или награды. Устраняй непреднамеренные пересечения. Линия реальной зависимости и декоративный указатель порядка должны различаться. Не создавай dependency только ради красивой линии; при отсутствии декоративных линий используй расположение, номера и текстовые переходы.
5. Центральный знак главы и рамка не вытесняют квесты к краям и не заставляют прокручивать огромный пустой холст. Периметр, как в первом референсе, используй только там, где коллекция остаётся легко читаемой. Основная ветка и точка старта видны при первом открытии.
6. Сделай удобный выбор 32 вкладок, тематическую группировку, понятные названия и переходы между связанными темами. Используй штатные поиск, pin, zoom/pan и autofocus там, где они доступны в установленной версии; не подменяй их вымышленными настройками.
7. Обычный квест, коллекция, справка и важная веха различимы по согласованным форме, размеру или рамке. Цвет дополняет смысл, а не является единственным обозначением. Состояния доступно/выполнено/награда не получена/нативно заблокировано читаются на любом фоне.

Оформи каждую из 32 глав осмысленно. Общая система сетки и стилей нужна, но одинаковая механическая раскладка для кухни, железной дороги и кампании не подходит.

## 6. Фоны: только настоящие Minecraft-миры

**Никакой генерации изображений AI, AI-upscale, нейроиллюстраций «похожих на Minecraft» или стилизованных под игру выдуманных пейзажей.** Это относится и к попытке замаскировать такую картинку пикселизацией. Не использовать imagegen как запасной способ закончить задачу.

Используй реальные внутриигровые скриншоты. Приоритет — уже существующие подходящие скриншоты JEM либо новые кадры из запущенного JEM: без HUD, чата, курсора, меню и видеоплеера. Можно подготовить небольшие сцены в отдельном тестовом мире. Если берёшь внешний игровой скриншот, проверь происхождение и возможность использовать его в распространяемом паке; сохрани источник.

Подбирай сцену по главе: дом/мастерская для старта, поля и теплица для фермы, настоящая кухня для еды, механизм Create для инженерии, причал для моря, соответствующие биомы и пещеры для экспедиций, реальная арена или измерение для боя. Можно повторно использовать подходящий фон в родственных главах, но не ставить одну случайную картинку во все 32.

Фон должен оставаться фоном: спокойная композиция, умеренная яркость, читаемые силуэты блоков, без чрезмерного bloom, тумана и визуального мусора. Допускаются кадрирование, уменьшение и неброское затемнение. Рамки, панели и заголовки дают достаточный контраст. Сохраняй пропорции кадра; не растягивай его и не делай текст частью фоновой картинки.

Четыре Homestead PNG — референсы. **Не вырезай из них фон вместе с квестами, чужим логотипом или элементами YouTube.** Внешний рисованный пейзаж, видимый на некоторых скринах, также не отменяет требования настоящих игровых фонов для JEM.

Храни финальные изображения локально в ресурсах сборки с нормальными ResourceLocation и возможностью замены ресурс-паком. Никаких сетевых загрузок при открытии главы. Размер текстур выбирай по фактическому отображению; не загружай все полноразмерные фоны одновременно и не декодируй их каждый кадр. Для новых кадров сохрани краткое описание сцены/источника; для внешних — автора, URL и условия использования.

Если окружение действительно не позволяет получить реальные игровые кадры, используй доступные подтверждённые скриншоты или явно перечисли недостающие сцены. Не подставляй AI и не заявляй, что визуальная часть закончена, если в ней заглушки.

## 7. Pixel-art иконки и поведение при наведении

У каждой вкладки и смысловой ветки должна быть узнаваемая тематическая иконка; у каждого задания — предмет/объект, соответствующий действию. Приоритет — штатные изображения и рендеры предметов установленного пака. Не заменяй всё одинаковыми книгами, сундуками, emoji или гладкими веб-иконками.

Если действительно нужен новый знак главы, сделай собственный пиксельный рисунок на целевой сетке или используй утверждённый ассет JEM. Размер выбирается под отображение: не назначай всем элементам 16×16. Чёткие квадратные пиксели, читаемый силуэт, ограниченная согласованная палитра, прозрачный фон. Масштабирование пиксельных спрайтов — без размытия; никаких уменьшенных случайных картинок и автоматического перевода фотографии в «pixel art». Не копируй логотип Homestead.

Раздели три уровня интерфейса:

| Действие | Что видит игрок |
| --- | --- |
| Наведение на иконку вкладки/ветки | Название и 1–2 короткие строки: чему посвящена ветка; прогресс, если он корректно доступен. |
| Наведение на узел квеста | Название, краткое условие, прогресс и короткая награда. Подсветка не перекрывает индикатор состояния. |
| Клик по квесту | Полная карточка с задачами, наградами, смыслом, практической подсказкой и переходом к следующей теме. |
| Наведение на предмет в карточке | Настоящий item tooltip, требуемое количество/прогресс и доступный переход к рецепту/применениям. |

Не превращай каждый hover в длинную статью, закрывающую карту. Подсказка помещается в экран и не мигает при движении между иконкой и её краем. Полные описания открываются кликом, как в третьем референсе; четвёртый показывает отдельный hover предмета внутри карточки.

Сначала используй нативные возможности FTB Quests/Library и установленной JEI-интеграции. Проверь фактическое поведение в игре. Если необходимая небольшая функция недоступна, реализуй минимальное совместимое дополнение; не переписывай весь quest screen ради одного tooltip. Сохрани привычные клики, Esc, pin, прокрутку и ресурс-пак совместимость.

## 8. Полезные подсказки вместо общих фраз

Текст для игрока — простой русский. Названия предметов согласованы с реальными локализациями. Не показывай игроку названия Java events, внутренние registry IDs, callback, scope и другие детали реализации.

Структура карточки:

1. **Что сделать:** точное наблюдаемое действие и количество.
2. **Награда:** конкретное содержимое, без загадочного «получи бонус».
3. **Зачем:** какую возможность игрок освоит.
4. **Совет:** где взять нужное, что применить, одна полезная особенность или частая ошибка.
5. **Дальше:** понятный переход в следующую тему, когда он полезен.

Условия и награда читаются сразу. Основное объяснение — несколько коротких предложений; дополнительную справку можно раскрыть отдельно. Советы не добавляют скрытых требований к зачёту.

Пример: «Поставь Water Wheel и Shaft»; прогресс отдельно для двух типов; награда — 32 Andesite Alloy, 32 Shaft и 60 очков опыта (`H11.01`). Совет объясняет передачу вращения и применение полученных деталей. Он не требует доказать работоспособность фабрики или проверить территорию.

Для необычного предмета объясни конкретное применение. Для предмета без рецепта — проверенный способ получения. Для босса — доступные в текущей версии способы подготовки, опасные атаки и подтверждённые иммунитеты; не выдумывай уязвимости. Для клавиш показывай актуальный keybind или путь к настройке, а не жёстко заданную букву. Ссылки на JEI и существующие книги должны работать; не создавай ещё одну параллельную энциклопедию, если соответствующая справка уже есть в универсальном гайде JEM.

## 9. Выполни работу полностью и проверь результат

Начни с полного извлечения карточек и сверки с установленными реестрами/конфигами. Затем проверь формат и весь путь выполнения на нескольких разных заданиях: размещение-коллекция, предметная коллекция, взаимодействие/урон, нативная победа. После этого перенеси все главы и примени согласованное оформление. Пилот нужен для проверки подхода, а не для сокращения итогового объёма.

Сохраняй изменения пользователя и существующие сохранения. Используй принятые в репозитории пути источников и механизм синхронизации клиентской/серверной сборок. Не создавай две независимо редактируемые копии одной книги. Если нужна генерация конфигов, повторный запуск должен сохранять IDs и не стирать ручные координаты/тексты. Не добавляй тяжёлые зависимости или отдельную платформу генерации квестов.

Проверь именно существенные риски:

- Все 596 исходных карточек отражены в таблице соответствия; все 32 главы присутствуют. Нет потерянных тематических веток, несуществующих предметов и случайно обязательных справок. Любое отличие от исходных количеств объяснено по конкретным ID.
- У каждого игрового задания не больше двух простых проверок; коллекции считают разные цели правильно. Советы не стали условиями, рекомендованный порядок не превратился в цепь блокировок.
- Все игровые карточки сохранили материальную награду из модов, итоговые количества и правильную семантику выбора. Ни оружия боссов, ни готового Nightfall-снаряжения, ни отключённых предметов в выдаче нет. Проверены разбиение больших количеств на стаки, отсутствие поддельных data-bearing предметов и нежелательных автоматических каскадов.
- Прогресс не удваивается от двух рук/повторного callback, корректно сохраняется и восстанавливается. Награды нельзя забрать повторно из-за обычного переподключения или повторного сигнала.
- Соло работает без `/smp`, боевой party и Raid; на сервере правильно разделены личный, командный и мировой прогресс. Готовый мировой флаг можно увидеть после входа, а не только в момент его изменения.
- SNBT и ресурсы реально загружаются. Нужные модули собираются. Проверены применяемые API, ресурсы и ссылки; проверки не сводятся к поиску ожидаемой строки в сгенерированном файле.
- В игре просмотрены все главы; для разных типов глав сделаны реальные скриншоты. Отдельно проверены hover, полная карточка, item tooltip, длинные русские названия, состояние завершения и невзятая награда. Проверь хотя бы 1920×1080 и 1366×768 с подходящими GUI Scale, включая более крупный интерфейс.
- Нет перекрытий, обрезанных подсказок, нечитаемых линий, отсутствующих текстур, растянутых фонов и декоративных элементов поверх кнопок. Книга не вызывает заметных зависаний из-за загрузки фонов или проверки событий.

Если игровой запуск недоступен, честно отдели выполненные проверки от непроверенного поведения. Продолжи доступную работу и укажи точный блокер. Не называй PNG-макет или HTML-preview доказательством работы в Minecraft.

## 10. Что должно быть в результате

1. Рабочие главы FTB Quests, награды, локализованные тексты, координаты и оформление всех тематических веток.
2. Необходимый небольшой мост событий/интеграций, реальные фоновые изображения и пиксельные иконки в ресурсах.
3. Таблица соответствия всех исходных карточек и краткий список обоснованных расхождений с HTML.
4. Краткий перечень происхождения визуальных ассетов и реальные игровые скриншоты для оценки результата.
5. Короткий итог: что реализовано, какие проверки пройдены, что действительно осталось заблокировано. Не выдавай незаконченные заглушки за готовые механики.

**Критерий успеха:** игрок открывает красивую, читаемую книгу, сразу понимает ближайшие действия и награды, узнаёт реальные возможности всего пака, а код отслеживает простые события вместо сложных сценариев.
