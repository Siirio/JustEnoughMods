# Ordinary startup registration corrections

The 2026-10-28 ordinary Server startup reached mod construction after the native harvest and cooking/fishing corrections. It exposed two concrete loading defects in the quest adapter source

- Forge EventBus 6.0.5 constructs listener wrapper names from package name, declaring class simple name, method name and event simple name. Both food receipts used an inner class named `Registration`, method `register` and `RegisterCapabilitiesEvent` in the same package. The wrapper names collided, so the Baking listener invoked the earlier Grape registration and Forge rejected a second registration of `GrapePotReceipt.Store`. The debug log shows Baking listener index 5 dispatching `GrapePotReceipt.Registration.register`. Distinct `registerGrapePot` and `registerBakingSurface` method names preserve each exact capability owner and eliminate this generated-class identity collision
- Mixin 0.8.5 tried to resolve the array owner of the direct `Mob[].clone()` invocation in `PetUtilityQuestWagonMixin` as a normal class, failed to find `[Lnet/minecraft/world/entity/Mob;`, and rejected the Mixin. `Arrays.copyOf(horses, horses.length)` preserves the same isolated snapshot without an array-owner virtual invocation in the Mixin

The exact installed `IEventListenerFactory.getUniqueName` bytecode establishes the wrapper naming rule. No capability registration was suppressed, no proof was weakened, and no wagon state or gameplay mutation was added. Source correction and packaging do not establish gameplay acceptance

The next ordinary startup completed native criterion registration and resource loading, then FTB's `SNBTParser.readList` rejected `jem_rescue_entry_bounds` because JSON serialization preserved a mixture of integer and fractional bounds. NBT lists require one tag type. The canonical compiler now emits those four coordinates as doubles, preserving their exact numeric values, all node coordinates and the separate JSON layout. This correction changes only generated FTB chapter definitions and needs no Java artifact replacement

With homogeneous bounds, FTB loaded all606 quests. The first ordinary world tick lazily loaded Simply Bows 0.1.4's `BlossomStormManager` and exposed an ambiguous `createStorm` selector. The four-argument overload delegates to the five-argument implementation, while only the latter performs `List.add` at bytecode offset294. The quest observer now pins the full five-argument descriptor and still observes the same native addition after success. No optional injection or missing-proof fallback was introduced
